# Adaptive Collaboration

Revenue Coach does not force the agent into a single role. It establishes a small collaboration contract for the active work, then lets the agent coach, assist, co-create, execute, or operate each workstream differently.

## Why skill level is not enough

Two people with the same skill may want very different help:

- an experienced designer with little time may delegate production;
- an experienced designer protecting a distinctive style may request only research and copy;
- a beginner may want the agent to execute quickly;
- another beginner may keep execution because learning is the product of the session.

The framework therefore separates capability, evidence, ownership, capacity, and objective. It records only the workstreams that matter to the current revenue experiment.

## Collaboration modes

| Mode | Agent does | User does | Good fit |
| --- | --- | --- | --- |
| Coach | questions, teaches, challenges, critiques | decides and executes | capability building or high user authorship |
| Assist | prepares research, briefs, raw material, and checklists | assembles the deliverable | specialist user with a support gap |
| Co-create | drafts and iterates | directs, selects, and edits | shared authorship or uncertain direction |
| Execute | produces the agreed internal deliverable | approves defined checkpoints | speed or missing production capacity |
| Operate | repeats a proven approved procedure | monitors exceptions and external actions | stable recurring workflow |

The safest default for uncertain creative work is a representative co-created POC. The output gives both sides better evidence than a long intake questionnaire.

## Example: social media template business

| User profile | User owns | Agent may own |
| --- | --- | --- |
| Visual designer | visual system and final production | niche research, concept options, copy, listing, critique |
| Campaign strategist | audience, objective, message, approval | editable design production, variants, resize, QA |
| Concept owner | product direction, claims, pricing, approval | research, positioning, copy, design POC, mockups, listing |
| Beginner learning design | practice and final decisions | instruction, examples, critique, corrective draft |

A minimum POC is normally a brief plus a representative small set—not an app, a huge template library, or an automated content factory. Full production begins only after the POC proves direction, quality, editability, and fit.

## Tool routing

Tools follow ownership. If the user owns design, the agent may only need a document for the brief. If the agent owns editable production, it can verify an available Canva, Figma, SVG, or equivalent path. If no suitable integration is active, it distinguishes a connectable option from a merely recommended one and provides a fallback.

Installation, account connection, subscription, sensitive upload, and external actions require explicit user approval. Custom apps or MCP servers remain behind the build gate.

## Optional subagents

When the host supports subagents, the main agent may delegate bounded AI-owned work such as market research, copy, design production, or QA. The main agent retains the user context, integrates results, and enforces acceptance criteria. User-owned work is never silently delegated.

Subagents are an optimization, not an architecture requirement. The same workflow must remain usable by a single agent.

## Recalibration

Update the collaboration contract when evidence changes:

- the POC shows the user wants more or less control;
- output quality requires stronger review;
- a repeated process becomes safe to operate;
- the user's time, learning objective, or available tool changes.

Do not permanently label the user from one task. Capability and preferred assistance may differ across market research, strategy, design, copywriting, sales, and delivery.
